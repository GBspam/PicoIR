# PicoIR v0.1 — recovered design specification

This document summarizes the initial specification found in the recovered project conversation. It is not a recovered source-code release.

## Goal

Build a universal infrared communications platform for the original Raspberry Pi Pico (RP2040), spanning raw waveform capture/transmission, consumer remote protocols, IrDA, Game Boy Color infrared, and selected GBA accessory profiles.

## Architecture intent

- TinyUSB device with two independent CDC interfaces.
- CDC0: transparent binary byte pipe with no diagnostic text.
- CDC1: configuration, diagnostics, and IR tooling console.
- C for USB, buffers, protocol engines, and hardware management.
- PIO/DMA for timing-sensitive transmit and receive waveform operations.
- MicroPython as a future high-level configuration/management layer.
- Discrete optical frontend; no dedicated IR encoder/decoder IC.
- Transmitter uses a transistor driver and current limiting; the Pico GPIO must not directly drive the high-current IR LED.

## Proposed GPIO assignments

| GPIO | Proposed function |
|---|---|
| GP0 | IR LED driver |
| GP1 | Digital IR receiver output |
| GP2 | Receiver enable/gain control |
| GP3 | Optional external hardware control |
| GP16 | Status LED |
| GP17 | Hardware activity LED |
| GP26 / ADC0 | Analog receiver monitor |

These are proposed assignments, not a validated schematic or board layout.

## Planned command families

The recovered specification includes status and protocol selection, remote learning/sending, raw RX/TX capture, and analyzer commands. The protocol roadmap includes NEC-family, Sony SIRC, RC5/RC6, Samsung, Panasonic/Kaseikyo, JVC, IrDA SIR then higher layers, and Game Boy profiles.

## Safety and validation notes

A wideband photodiode receiver and a conditioned digital receiver path were proposed. SIR, MIR, and FIR require separate hardware validation; FIR compatibility must not be assumed. Persistent settings require a reserved flash region and power-loss-safe storage before implementation.
